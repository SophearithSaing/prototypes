01 / Brief & foundation

Start with the story,
not the stack.

The project began with a single file: reference.png. A luminous career path rose out of a circular platform, surrounded by dimmer paths that could have been.

The goal was to translate that visual idea into a portfolio, not place the image behind some text. The gold path became the chosen journey; blue branches became alternative possibilities. Real content needed a quieter space alongside it.

THE FIRST DECISION

Make the atmosphere extraordinary. Keep the interface ordinary enough to understand. The result is a conventional, scrollable portfolio with an unconventional hero.

Why Vite, TypeScript, and vanilla Three.js?

This is a single page with a small amount of shared state: selected chapter, open dialog, animation preference, and sound. A component framework, router, and state library would add machinery without solving a pressing problem. Vite handles development and bundling; TypeScript checks the browser and Three.js interfaces.

The project uses Three.js 0.180, TypeScript 5.9, and Vite 7. Three.js is the only runtime package dependency. React and Next.js appear in the sample project descriptions, not in this site's implementation.

02 / Architecture

Let WebGL draw.
Let HTML speak.

Rendering the milestone text as 3D geometry would make the whole composition self-contained, but it would also mean rebuilding basic browser behavior: readable text, focus, keyboard activation, and accessible names.

Instead, the canvas is decorative and the cards are real buttons. The two systems share positions, not responsibilities. Three.js moves the camera; the browser renders the content.

One coordinate system at the boundary

Each frame, a node's world position is projected through the current camera. Normalized device coordinates run from −1 to 1; CSS positions run from the top-left corner of the stage. The conversion is small, but it is what makes the labels feel attached.

03 / The visual construction

Author the layout in screen space.

Purely world-space placement made a poor design contract for readable cards. Perspective changes how much space a world unit occupies. The solution was to start with the desired on-screen layout, then work backward into the scene.

A fixed layout camera has a 40-degree vertical field of view. Rays from normalized screen positions intersect a plane at y = 0.16. A cloned camera handles the subtle pointer movement and dragging without changing the layout camera.

Five vertical anchors sit at 75%, 60%, 45%, 30%, and 15% of the stage. Horizontal positions account for the measured card widths and a clearance allowance. The path keeps its perspective, while the labels get predictable breathing room.

The glow is several small tricks, together

A centripetal Catmull–Rom curve supplies the main path. It becomes two tubes: a narrow bright core with a radius of 0.026, and an additive gold layer with a radius of 0.059. Both use 440 tubular segments and seven radial segments.

The core's material color is deliberately above the usual 0–1 range: new THREE.Color(3.4, 2.3, 1.3). Bloom can pick out these bright values before ACES filmic tone mapping and sRGB output bring the image back to the display.

01 / RenderPassRender the scene and its HDR-valued materials.
02 / UnrealBloomPassStrength 0.43, radius 0.6, threshold 1.1.
03 / ShaderPassTone mapping, color conversion, and feathered alpha.

The final pass matters: bloom's output alpha is opaque. A custom shader restores a feathered stage edge so the canvas blends into the page instead of looking like a rectangular image pasted on top.

Thirty blue-violet curves, 1,150 stars, and 116 moving particles add depth. A generated radial texture supplies the sprite halos. Portal rings and a noise-based atmosphere complete the illusion. There are no scene texture downloads and no physically lit shadow system.

04 / Loading & lifecycle

The best frame is the one
you don't render.

A portfolio should not keep spending GPU time after its hero has scrolled away. The render loop checks document visibility, intersection with the viewport, usable dimensions, context health, and disposal state before requesting work.

Paused does not mean incapable of drawing. A paused scene can render once after a resize or focus change, but the frame does not continuously reschedule itself. Opening a dialog also pauses the scene; closing it restores the visitor's motion preference.

  • Cap pixel density at 1.5. High-DPI screens otherwise multiply the number of pixels being shaded.
  • Soften bloom at a smaller resolution. Its dimensions are 0.72 of the composer's physical dimensions; the main image stays sharper.
  • Batch the small things. Alternative threads share a LineSegments object; stars and moving particles use Points objects.
  • Own the lifecycle. Resize replaces and disposes geometry. Teardown cancels RAF, disconnects observers, removes listeners, and disposes GPU resources.

Let the content arrive before the renderer

The first production build put roughly 554 kB of minified JavaScript into one bundle. The page now creates its HTML before dynamically importing the scene. A failed import or synchronous scene initialization switches the already-created buttons into a CSS timeline.

The chunk rule distinguishes the library's examples/effects from its core. It checks node_modules/three/, not just three/src/, because the package also resolves through its built modules.

05 / Responsive design

Give the words room to reflow.

The desktop hero is an art-directed composition: introduction on the left, timeline on the right. That layout works at a wide aspect ratio. Shrinking the entire scene into a phone-shaped rectangle does not.

At 700 pixels and below, the hero becomes a normal-flow column. Introduction first, then a full-width scene, then the controls. Decorative alternative-path cards disappear; the real milestones stay.

THE BUG THAT CHANGED THE LAYOUT

With external fonts blocked, fallback type wrapped differently at 320px. A fixed scene offset let the text collide with the timeline. Moving the sections into document flow fixed the assumption, not just the symptom.

The mobile scene is still a deliberately sized composition: 600px tall, or 595px on the smallest breakpoint. Card widths reduce to 150px and then 130px. The renderer measures those widths when rebuilding positions.

This is responsive, but it is not a general-purpose timeline layout engine. The five anchors and their spacing are authored. Adding a sixth milestone requires changes to the scene and CSS fallback, not only another object in the content array.

06 / Browser-native interactions

Human interactions.
Honest promises.

Use a real dialog

Chapter notes, project descriptions, and contact share a native <dialog>. Calling showModal() provides modal behavior and Escape dismissal. The application manages body scroll, focuses the new title, and updates the scene's pause state.

Template HTML is authored locally. This is not a safe rendering pattern for arbitrary remote content. The visitor's form data is used in an encoded email URL, not inserted into these HTML templates.

Contact without pretending there is a backend

The form uses native required-field and email validation, then opens a prefilled mailto: draft. Both subject and body are passed through encodeURIComponent, so characters such as &, ?, and # do not change the URL's structure.

The button says “Open email draft,” not “Send message.” A mail client must still be configured, and the visitor must send the email. Copy-email is the alternative. There is no server submission, delivery confirmation, or claim that a message has been received.

Sound is an invitation, not an entrance fee

Ambient sound is created on request with the Web Audio API. Four sine oscillators at 110, 164.81, 220, and 277.18 Hz pass through a 380 Hz low-pass filter. Slow oscillators modulate the individual gains to give the tone a gentle breathing quality.

No audio starts on page load. Sound suspends in a hidden tab. System reduced-motion preferences default the scene to paused, while the visitor can explicitly resume it. Pointer dragging ignores interactive HTML targets, and the canvas allows vertical touch panning.

07 / Debugging notes

The parts the screenshot
didn't show.

The first good-looking frame was not the finish line. These fixes came from using the controls, changing viewport sizes, and deliberately removing browser capabilities.

FIX 01Pausing the scene hid the dialog.

An early global animation-pause rule also stopped the dialog's entry animation at opacity zero. It could freeze the header offscreen too. The final version pauses the Three.js controller, not every CSS animation in the document. Dialogs and navigation remain usable.

FIX 02The mobile contact icon had no name.

The visible “Let's talk” label is hidden on narrow screens, and the arrow SVG is decorative. An explicit aria-label gives the remaining icon-only button its accessible name. Decorative visuals cannot be the only way to understand a control.

FIX 03Feedback belonged inside the dialog.

A normal page toast cannot outrank a native modal's top layer, regardless of its z-index. Copy-email feedback now updates the contact form's own status text, where it is visible and announced.

FIX 04A fixed delay was not a reliable assertion.

In headless Chrome with software WebGL, a screenshot could catch a dialog mid-animation. A 400ms sleep was occasionally too short under load. The check now waits for the actual visual state instead of guessing when it will arrive.

Other second-pass fixes included shortening milestone subtitles, increasing muted-text contrast, giving duplicated SVG gradients unique IDs in project dialogs, and keeping the mobile artwork inside its frames.

08 / Verification & handoff

Checked, not assumed.

Verification covered both the development page and the built output. The following records checks performed during the portfolio build, not a promise of universal browser or device coverage.

  • BUILD
    Type checking and production outputnpm run build runs tsc --noEmit before Vite. The final build completed without errors or chunk-size warnings.
  • LAYOUT
    320, 360, 390, 700, 768, 1024, and 1440pxBrowser checks verified no horizontal page overflow and that milestone cards stayed within the viewport.
  • INPUT
    Interactions, not just screenshotsChapter navigation, project dialogs, Escape, focus restoration, sound and pause toggles, clipboard copying, form validation, and encoded email drafts were exercised.
  • A11Y
    Automated accessibility checksAxe scans reported no violations under the tested WCAG 2 A/AA and 2.1 AA rule tags in desktop, mobile, milestone, and contact views. This is not a complete accessibility audit.
  • EDGES
    Remove the happy-path assumptionsChecks covered WebGL initialization failure, blocked external fonts, reduced motion, an explicit motion override, and dialogs opened while the scene was manually paused.

These browser checks used Chrome, including a software WebGL configuration. The ad hoc Playwright and axe scripts lived outside the repository during development; a persistent automated test suite is not included in the project.

What remains intentionally unfinished

  • Personal content. Career entries, project concepts, email, and metadata are sample material. Replace them before publishing.
  • A general timeline engine. Five graphical nodes are hard-coded. Card clearance is a heuristic, not an overlap solver.
  • Full no-JavaScript content. The portfolio generates its interface in JavaScript. Its HTML has a no-script contact message, not a server-rendered portfolio. This journal, by contrast, is readable without JavaScript.
  • Broader device testing. Desktop automation does not establish mobile GPU performance, battery impact, cross-browser compatibility, or Core Web Vitals.
  • Transactional scene setup. Normal disposal is thorough, but a failure halfway through initialization can leave resources without a returned disposer. This is worth hardening before expanding the renderer.

The small runbook

Deploy dist/ to a static host. For source development, use npm run dev. This journal lives at public/build-notes.html; Vite copies it unchanged to dist/build-notes.html.

No server is needed to open this journal directly. Its CSS, diagram, and optional copy/navigation helpers are all in the HTML file. The code excerpts are notes, not executable examples embedded in the page.

01 / INTENT

The requirements became three rules.

The product brief was only seven lines long. Instead of adding a full note-taking system, the implementation protects the behavior those lines imply.

RULE 01

Open means ready

Focus starts in the editor. There is no welcome screen, file picker, workspace setup, or save decision between launch and the first character.

RULE 02

Drafts are not files

Working state is restored automatically. Export is a separate, intentional action for the moment temporary thinking becomes something permanent.

RULE 03

The keyboard is enough

Tabs, export, help, and exit all have direct shortcuts. Mouse support is unnecessary, keeping the interaction model small and predictable.

02 / STACK

Charm tools, each doing one job.

The app uses the Charm ecosystem rather than building terminal input, editing, and styling from raw escape sequences.

BUBBLE TEA Owns the event loop, terminal lifecycle, messages, commands, and alternate-screen rendering.
BUBBLES Provides the multiline textarea, export path input, cursor behavior, scrolling, and editing keys.
LIP GLOSS Provides the blue palette, tabs, border, spacing, overlays, and width-aware terminal layout.
GO STDLIB Handles JSON sessions, paths, file permissions, atomic replacement, time, and Unicode-safe counts.
main.go / composition root
func run(in io.Reader, out io.Writer) error {
    store, err := newSessionStore()
    // Missing state is a valid first launch.
    session, err := store.load()

    model := newModel(store, session)
    program := tea.NewProgram(
        model,
        tea.WithInput(in),
        tea.WithOutput(out),
        tea.WithAltScreen(),
    )
    _, err = program.Run()
    return err
}
03 / LOOP

Everything is a message.

Scratchpad follows The Elm Architecture used by Bubble Tea. State stays in one model, events transform that model, and the view is recreated from the result.

Message A key press, resize, cursor blink, or autosave timer arrives.
->
Update The active mode handles it and returns changed state plus optional work.
->
Model Tabs, active index, inputs, dimensions, status, and revision remain together.
->
View Lip Gloss renders tabs, the bordered editor, footer, and active overlay.

Why this matters: the filesystem is kept out of rendering, and the view never becomes a second source of truth. Given a model, the same terminal frame is produced every time.

04 / RUNTIME

From keystroke to safe draft.

Typing remains immediate because persistence is delayed just enough to combine a burst of edits into one disk write.

Key press

Edit active tab

The Bubbles textarea applies cursor movement or modifies its value.

Revision +1

Mark changed

The model increments a revision and schedules a timer tagged with that exact revision.

350 ms

Debounce

Older timers become harmless when newer typing has already advanced the revision.

Latest only

Persist session

The current tabs and active index are serialized only when the timer is still current.

Crash-resistant state

Replace, never rewrite.

Draft JSON is not written directly over the last known-good session. A temporary sibling file is completed first, then moved into place as one filesystem operation.

01Encode all tabs, the active index, the next tab ID, and schema version as JSON.
02Create a temporary file beside the session with private 0600 permissions.
03Write, sync, and close the temporary file so its content reaches storage.
04Rename it over session.json, atomically replacing the previous snapshot.
05 / DECISIONS

Deliberately less product.

Most of the design work was deciding what Scratchpad should not ask the user to manage.

D1

Autosave, not save state

No dirty markers or confirmation dialogs. Draft persistence is infrastructure, not a task the user has to remember.

D2

Export stays explicit

Ctrl+S asks for a path and writes only the current tab. A draft becomes a normal file on the user's terms.

D3

Titles derive from content

The first non-empty line names a tab automatically. There is no separate rename workflow to interrupt capture.

D4

JSON over a database

The state is one small versioned snapshot. A database would add migrations and operational weight without improving this workload.

D5

No line-number gutter

Notes are prose-first, and terminal mouse selection copies rendered cells. A clean gutter preserves frictionless selection and copying.

D6

One package, small seams

The app stays in package main, while storage and UI are separated by files and a tiny store value that tests can redirect.

06 / SOURCE

A small codebase with visible seams.

There is no framework around the framework. Each file corresponds to a concrete responsibility.

main.go

Boot

Find state, restore a session, configure Bubble Tea, and report startup errors.

model.go

Interact

Own tabs, key handling, autosave scheduling, export mode, sizing, and terminal rendering.

store.go

Persist

Version the session format and perform private, atomic writes in the user config directory.

*_test.go

Verify

Cover round trips, permissions, restoration, tab lifecycle, export, autosave, and narrow layouts.

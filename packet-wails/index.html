Packet desktop HTTP client. Technical overview.

Packet is a keyboard-oriented desktop HTTP client implemented with Wails, Go, React, and TypeScript. This report describes the application architecture, request processing, Postman import, cookie handling, JWT signing, environment configuration, and platform build process.

01 / THE BRIEF

Scope and technical requirements.

The application covers request composition and execution, response inspection, local authentication and cookie state, Postman collection import, keyboard navigation, and reusable environment variables.

Interface structure

Collections are shown in a sidebar, open requests use tabs, and request editing is positioned above response inspection. Common actions have keyboard shortcuts. The visual system uses a dark neutral palette with yellow for active states and primary actions.

02 / ARCHITECTURE

Three-layer application structure.

Wails binds the TypeScript interface directly to Go methods. The Go HTTP client executes requests outside the WebView's CORS model. Cookie behavior comes from the standard library, and JWT signatures are calculated in the local process.

03 / REQUEST FLOW

Request processing sequence.

01

Resolve config

The active environment substitutes {{name}} and ${name} across the request.

02

Sign auth

HS256, HS384, or HS512 signs the resolved JSON claims with the local secret.

03

Attach cookies

Go’s cookie jar selects valid cookies for the target URL and adds them automatically.

04

Execute native HTTP

The Go client sends outside the WebView, follows redirects, and enforces a timeout and size cap.

05

Inspect result

Status, duration, size, body, response headers, and effective request headers return to React.

04 / FEATURE ENGINEERING

Implemented capabilities.

{ }

Postman import

Flattens nested v2.0/v2.1 folders, preserves methods, URLs, queries, headers, and bodies, and converts collection variables into a new configuration.

⌘

Keyboard navigation

A searchable command palette sits alongside direct shortcuts for send, URL focus, new request, import, sidebar, environments, and zoom.

CK

Cookie management

A standards-compliant cookiejar.Jar captures Set-Cookie responses and replays matching cookies without duplicate headers.

JWT

Local JWT signing

Editable JSON payloads become HMAC bearer tokens as the secret changes. Signing stays inside the Go process.

ENV

Environment configs

Multiple named profiles persist locally. Variables can be enabled, masked as secrets, switched globally, and resolved at send time.

↗

Window scaling and build targets

The native window resizes to 760×520, the interface zooms from 80–200%, and the same source cross-compiles to Windows AMD64.

05 / BUILD TIMELINE

Implementation sequence.

FOUNDATION

Wails shell and Go application service

Configured the Wails application shell, embedded the Vite output, defined request and response contracts, and established method bindings between TypeScript and Go.

CORE LOOP

Request composition and response inspection

Added method selection, query/header tables, JSON body editing, timing, byte counts, response formatting, and multi-request tabs.

AUTH + STATE

Cookies, JWT, collections, and persistence

Implemented the cookie jar, HMAC signing, recursive Postman parsing, collection filtering, and local workspace persistence.

VALIDATION

Import crash fix and regression coverage

Normalized missing Postman arrays on both sides of the Wails bridge and added tests for minimal collections, nested imports, JWT claims, and cookie replay.

INTERFACE

Responsive sizing, zoom, and environments

Added compact breakpoints, persistent UI scale controls, named configurations, secret masking, template resolution, and Postman variable migration.

PLATFORMS

Linux workflow and Windows output

Encoded Wails build tags and WebKit detection in Make targets, documented Linux dependencies, and verified an 11 MB Windows GUI executable.
